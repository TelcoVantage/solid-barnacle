# Chat Ticket Script (Genesys Cloud)

Modernisation of the agent script used on the chat / web messaging channel: the
"User's inputs" page with the Create Ticket form, and the custom action behind the
Submit button.

| Folder | What it holds |
|---|---|
| `mockup/agent-ticket-page.html` | Visual mockup of the modernised page with build notes. Open it in a browser. |
| `docs/01-page-build.md` | Component-by-component recipe to build the page in the Script Editor. |
| `docs/02-create-ticket-action.md` | The redesigned Create Ticket custom action and the Reset action. |
| `docs/03-flow-and-queue-wiring.md` | Architect inbound message flow, participant data keys, queue assignment, Messenger. |
| `data-actions/` | Input/output contracts and response templates for the two data actions. |
| `scripts/` | Where the exported `.script` file lives so it can be imported through the GUI. |

## How the GUI import works

Genesys Cloud imports scripts from **Admin > Digital and Telephony > Interaction Assets >
Scripts > Import** (older menus: Admin > Contact Center > Scripts). The file is the
`.script` export produced by the same page's **Export** button. Its contents are JSON,
but the schema is not published by Genesys and is generated by the editor, so the
reliable way to get an importable file is:

1. Build the page and actions once in the Script Editor following `docs/`.
2. Select the script in the list and click **Export**.
3. Commit the downloaded `.script` file to `scripts/`.
4. From then on, anyone with the Scripter permissions can **Import** it (or select the
   existing script and click **Replace**) into any org.

Data actions are referenced inside the export by their IDs. When importing into a
different org, create the data actions there first and re-select them in the two
Execute Data Action steps after import.

Permissions needed to import: all permissions under *Scripter > Script*, plus
*Scripter > Published Script > Add* and *View*. The importing user needs user-level
(not group-inherited) access to the org.
