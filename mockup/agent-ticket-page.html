Preview state:
Customer bannerHorizontal stack container. Read-only text bound to {{fullname}}, plus chips for {{Scripter.Media Type}} and queue. Replaces the loose “Fullname: / Email: / Location:” rows.
Customer details cardVertical stack with two-column pairs. Values are read-only text. Email and interaction ID get a Scripter.Copy to Clipboard button so agents stop retyping them into the ticket.
Create ticket cardTwo Dropdowns (ticketCategory, ticketPriority) and one Text input with Multiline = Yes and Requires Value = True, bound to ticketDescription. Container Visible is bound to the showForm variable.
Submit buttonClick Action runs the custom action “Create Ticket”. Disabled is bound to isSubmitting, so a double-click can’t create two tickets.
Three state panelsMarkdown components, each in its own container with Visible bound to showPending, ticketCreated or ticketFailed. Only one is ever on screen, and the agent is never left staring at a blank {{ticketStatus}}.
Ticket numberComes from the data action output ticketNumber. The current page prints {{InteractionId}}, which is the output variable name, not a ticket number; rename it so the log table and the page agree.
Failure pathThe Create Ticket data action returns ticketFailed and ticketMessage alongside the return code, so a logical failure shows up without the script needing an if/else it doesn’t have. A hung request is covered by the Cancel button, which runs the “Reset Ticket Form” action.

Custom action · Create Ticket (redesigned)
  1. Set Variable · isSubmitting = true, showPending = true, ticketCreated = false, ticketFailed = false, ticketDone = false.
  2. Data Actions.Execute Data Action · Create Ticket (v9). Inputs: fullname, email, location, ticketCategory, ticketPriority, ticketDescription, Scripter.Interaction ID. Outputs: ticketDone, ticketReturnCode, ticketNumber, ticketMessage, ticketCreated, ticketFailed, ticketOutcome.
  3. Wait Until ticketDone Equals true
    3a. Execute Data Action · Insert Data Table Row (Chat Logs) with interaction ID, agent ID, ticketNumber, ticketOutcome, ticketReturnCode, ticketMessage, category, priority. Runs for success and for failure.
    3b. Set Variable · showPending = false, isSubmitting = false, showForm = false. The panels then show themselves from ticketCreated / ticketFailed.

Waiting on ticketDone rather than on ticketReturnCode = 0 is the key change: a non-zero return code no longer leaves the action waiting forever and the agent with no feedback.
